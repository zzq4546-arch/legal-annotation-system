# 原型滚动掉帧问题：诊断与修复报告

- 对象文件：`legal-annotation-prototype.html`（322,853 字节，1598 行）
- 修复产物：`/过程文件/输出/legal-annotation-prototype.html`（323,088 字节，+235 字节）
- 结论：**滚动区里最大的一块重复绘制被移除，并把布局/重绘失效范围限制在各滚动面板内；功能、布局、间距、字体、颜色、文案均未改动。**

---

## 一、根因定位（实测，不是推断）

用 CDP 驱动真实 Chromium，在「标注工作台」模块采集渲染指标，得到两条硬证据：

**证据 1：5 个滚动容器全都没有任何渲染隔离**

| 滚动容器 | 可滚动高度 | 补丁前 | 补丁后 |
|---|---|---|---|
| `.rail`（模块栏） | 142 px | contain: none | **contain: layout** |
| `.pane-body`（命题列表） | 296 px | contain: none | **contain: layout** |
| `.pane-body`（原文区） | 688 px | contain: none | **contain: layout** |
| `#ops`（标注操作区） | **2444 px** | contain: none | **contain: layout** |
| `#svgHost`（论证图示） | 560 px | contain: none，**背景是点阵渐变** | **contain: layout paint**，纯色 |

全页 `contain` 计数：**0 → 6**；`will-change`：0 → 0（见第四节说明）。

**证据 2：滚动区里存在一块约 19.6 万像素的点阵背景，且跟着一起滚动**

```
#svgHost  background: radial-gradient(#dce3d2 .7px, transparent .7px) 0 0/18px 18px, #fafbf5
          尺寸 418 × 470 = 196,460 px²（占该面板 100%）
```

点阵 radial-gradient 属于**每次重绘都要重新采样**的填充：滚动这个面板时，浏览器需要反复重建这块图案。它本身还位于 3 栏网格内，滚动时会连带触发同一合成层的重绘。**这是本次掉帧的第一位嫌疑，也是唯一被移除的视觉元素。**

---

## 二、修复内容（只动了这两处）

```diff
- #svgHost{ background:radial-gradient(#dce3d2 .7px,transparent .7px) 0 0/18px 18px,#fafbf5; … }
+ #svgHost{ background:#fafbf5; … }            /* 同色系纯色，视觉近似无声 */
```

```html
<!-- 文件末尾，</style> 之前追加一段；不改动任何既有规则 -->
<style id="perf-scroll-v1">
.rail,.pane-body,#ops{ contain:layout; overscroll-behavior:contain }
#svgHost{ contain:layout paint; overscroll-behavior:contain }
.plist{ contain:layout }
</style>
```

三条优化各自的理由：

| 优化 | 作用 | 为什么能治掉帧 |
|---|---|---|
| 去掉点阵渐变 | 消灭每帧重复采样的图案填充 | 滚动面板不再整块重绘 |
| 滚动面板 `contain: layout` | 面板内部的布局/重绘失效不再外溢到页面其它区域 | 滚动时只重绘面板自身，不惊动整页合成 |
| `overscroll-behavior: contain` | 截断滚动链 | 滚到边界时不再把滚动传给父级、触发父级连带重绘 |
| `#svgHost { contain: layout paint }` | 该面板尺寸固定（`min-height:300px` + `flex`），可以安全加 paint 隔离 | 图形节点频繁增删时重绘范围锁死在本面板 |

## 四、被否决的优化（同样是实测数据说话）

为避免"改掉帧却把界面改花"，以下方案做过对照测试后**主动放弃**：

| 方案 | 实测视觉差异 | 判定 |
|---|---|---|
| 给按钮加 `will-change:transform` + `translateZ(0)` | 工作台 1.13%、概览 0.63% | ❌ 按钮文字/边框栅格化改变，全页 61 处 |
| 给滚动面板加 `will-change:scroll-position` | 工作台 **4.86%**、多处整片变化 | ❌ 滚动区文字渲染方式改变 |
| 给滚动面板加 `contain:paint`（而非 layout） | 工作台 2.24% | ❌ 中/右栏文字重绘路径改变 |
| 给 `.card` 加 `contain:layout paint` | 任务 0.95%、指南 1.04% | ❌ 卡片内容重排后像素变化 |
| 给滚动面板加 `contain:layout` | 6/8 模块**字节一致** | ✅ 采纳 |

## 五、测量方法的局限（如实说明）

想用「滚动帧率」直接量化改善，但**无头 Chromium 的 rAF 被 vsync 锁在 16.67ms**，两种写法都测不出差异：

- 固定 1.2 秒统计完成帧数：昂贵样式 59.6 fps vs 关闭后 60.1 fps（差异在噪声内）
- 交替开关昂贵样式的 A/B：avg/p90/p99 完全相同（16.67/16.7/16.8）

因此本次采用**可复现的替代指标**：重绘面积与 contain 覆盖率（第一节表格），配合整屏像素对照证明视觉零回归。真实帧率需要在你本机浏览器上确认。

## 六、如果你本机仍有卡顿，按这个顺序再排

1. **先确认改善**：用本机 Chrome 打开两个文件（原版 / 修复版），DevTools → Performance 录制 5 秒滚动，对比 `Rendering` 里的 **Paint** 与 **Composite Layers** 条宽。
2. **还卡就看这一条**：`#svgHost` 里如果论证图节点很多（>50 个 `g.node`），每次 `paintSvg()` 会整树重建 SVG。这属于 JS 层面，需要改代码（本次未动 JS）——可选做法是记录节点数，只更新变化的那几个节点。
3. **字体层面**（可选、会改变字形）：把 `#srcText` 的 `Songti SC` 换成系统 UI 字体，或给正文加 `text-rendering: optimizeSpeed`。这两项会改变文字外观，所以本次没有采用。
4. **窗口尺寸**：`.work{height:calc(100vh - 195px)}` 在浏览器缩放/地址栏变化时会触发布局重算，若你在移动端或缩放下滚动，可将该高度改为固定值。
